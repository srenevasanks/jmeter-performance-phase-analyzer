# setUp — actual validation screenshots

**27 original screenshots · v1.1.1 evidence · Partial overall compatibility**

Configured load: 100 users; setup lifecycle; 20/100/absent seconds. Executed alone in the native setup lifecycle; no gradual ramp-down.

[HTML sample](../../../examples/setup/report.html) · [Excel sample](../../../examples/setup/report.xlsx) · [All nine groups](../README.md) · [Compatibility](../../../docs/COMPATIBILITY.md)

Each image is copied byte-for-byte from this group’s own original validation screenshots folder, with its original filename. No replacement capture, cross-group substitution, redrawing or performance rerun was used. Original title bars can contain local validation paths; they are capture context, not installation dependencies. Existing curated gallery images remain separate.

HTML images are browser captures; Excel images were captured in WPS Office. These local mock-service results illustrate plugin validation, not production performance or new v1.1.2 GUI verification.

## Evidence limits

- No separately named completed Dashboard screenshot is available.
- No separately captured normal-traffic Live Metrics screenshot is available; the available history/failure/recovery views are linked below.
- The Dashboard capture records stale selection. Normal-traffic live capture was missed before the burst; failure/recovery and completed Live Metrics views are available.
- Manual images are unapplied analytical previews, not evidence of a separate manual-configured performance execution.

Native detection reads configuration. Missing phases remain unavailable; a file named ramp-down does not establish native ramp-down support. Open workloads schedule arrivals/sec, not users. [Detailed validation limits](../../../docs/VALIDATION.md).
